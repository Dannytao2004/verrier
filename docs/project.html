triangulate-agent

An LLM agent that estimates a number which has not been published yet, from public evidence that has, and shows exactly which evidence and assumptions every estimate rests on.

Python 3.14LangGraphDeepSeek (deepseek-flash)Wayback Machine snapshotsMonte CarloFastAPI + vanilla JSpersonal project, 2026

The problem

Many useful numbers are released weeks after the period they describe (monthly park visits, births, airport traffic), or are never released at all. Asking a language model for them directly produces a confident guess with no audit trail. This project asks a different question: can an agent assemble the side evidence that is public (earlier releases, related series, partial counts, published shares) into an estimate that beats simple baselines, without letting the model invent or compute numbers?

How it works

Planpin the exact target; design computable routes
→
Human approvalkeep or drop each direction
→
Parallel sub-agentssearch → archived page → quoted numbers
→
Judgecorroborate, discard, declare assumptions
→
Checkscode dry-run, input audit, one repair
→
Computecode only: methods, Monte Carlo, weights
→
Answerestimate, interval, evidence ledger
  • The model proposes, code decides. The model plans routes (total × share, last year × change factor, capacity × utilisation) and picks methods; every number is parsed, converted and combined by Python.
  • Every observed number is verifiable. Extractors must quote the source verbatim; code checks the quote against the page, parses the number and scale word, and rejects points whose year does not appear on the page.
  • Assumptions are first-class and labelled. When a coefficient has no source, the judge may declare it with a range, a rationale and what would falsify it. Code rejects assumptions that disguise the target itself, widens ranges that are too narrow, and shows how much of the final uncertainty comes from assumptions rather than evidence.
  • Errors are caught in a loop, not in one pass. Code dry-runs the judge's methods; a separate model call audits whether each input really denotes what the formula needs (it catches "a growth figure used as a level" or "a neighbouring park's total used as this park's"); failures, or routes that disagree by more than 3×, go back to the judge once.
  • Backtests cannot peek. In a backtest the agent only reads Wayback snapshots dated before the cutoff, and a sentinel scans everything the analysts see for the true value.

Interim, and not all wins. On the Japanese migration question the agent produced no estimate: only 3 of 44 pages were usable (the rest were PDFs, official pages the fetcher could not decode, or pages with no archived copy before the cutoff), and the judge then treated a percentage change as an annual level, which code rejected; the direct answer won there. On the NHS question the search step wrote the published figure into one query, because web search cannot be limited by date; only archived pages from before the cutoff were read, but which pages were chosen may have been influenced. The pre-registered success criteria cover all four questions and are judged after 28 October.

What building it taught me

  • The first assumption-enabled version produced no estimate on 3 of 4 questions; the next produced meaningless numbers (an estimate of 2 visits, 0 births) on 4 of 8 runs. Every fix since then is a general rule driven by a logged failure, and every version is tagged in git with its pre-registered evaluation.
  • Several checks are neither pure code nor pure model: code can tell that a formula multiplies two ratios, but only a model can tell that "births up 2,781" is not "last July's births". The audit step combines both.
  • Some guards I tried made things worse and were reverted, e.g. a magnitude band that would have rejected correct answers because per-country figures looked like national totals.

Known limitations and next steps

  • Questions with a few discrete outcomes (e.g. the next central-bank rate decision) need probabilities per outcome, not a continuous estimate; this mode is being added.
  • Retrieval of non-English official statistics is weak; when the target value is already published, the agent should report it rather than blend it with estimates.
  • Runs take 5–40 minutes and cost roughly US$0.3–0.6 each.
